# APIMatic integration

Crumb uses two distinct APIMatic resources:

1. **Runtime:** the official `@paypal/paypal-server-sdk` **2.5.0**, generated by APIMatic. This dependency is pinned in `package.json` and `package-lock.json` and runs in Next.js Node.js server routes.
2. **Development:** APIMatic's **PayPal Context Plugin 0.4.1**, installed into Codex and consulted during the integration review. It is not a browser widget, a hosted payment service, or a Vercel dependency.

## Runtime flow

`lib/service.js` → `lib/paypal.js` → `lib/paypal-apimatic.js` → Orders / Payments controllers → PayPal sandbox.

| Action | SDK operation |
| --- | --- |
| Start an approved order's checkout | `OrdersController.createOrder` |
| Check or recover payment status | `OrdersController.getOrder` |
| Capture a buyer-approved payment | `OrdersController.captureOrder` |
| Refund after merchant approval | `PaymentsController.refundCapturedPayment` |
| Recheck an existing refund | `PaymentsController.getRefund` |

The adapter converts the service's snake_case request fields to SDK models and returns original response JSON. This preserves decimal amount strings, `custom_id` and nested captures for the existing server-side verification. Stable `PayPal-Request-Id` headers remain attached to writes. The client uses sandbox explicitly, a 20-second timeout and zero automatic retries. SDK request details never appear in customer errors. Webhook signature verification stays on the existing PayPal Notifications REST endpoint because the official SDK has no Notifications controller.

`PAYPAL_TRANSPORT=apimatic` is the default. Set it explicitly in Vercel and redeploy. `PAYPAL_TRANSPORT=rest` remains an explicit rollback option; there is no silent transport fallback. Keep the existing PayPal sandbox client ID, secret and webhook ID. No APIMatic API key is needed.

The SDK import is visible to Next.js dependency tracing and the package is declared in `serverExternalPackages`; a webpack-ignore import would risk omitting it from the Vercel server bundle.

## Context Plugin scope

Install for Codex with `npm run setup:apimatic-context`. The installed plugin's TypeScript guide currently describes a different generated package (`paypal`, `PaypalClient`) from the official PayPal Server SDK (`@paypal/paypal-server-sdk`, `Client`). We reviewed that distinction and verified the official SDK's controllers, schemas and configuration against its installed source. Do not copy one SDK's signatures into the other. The plugin's package-specific workflow does not govern the official SDK adapter. No claim is made that the plugin originally generated all of Crumb or produced measured development-time savings.

## Validation on November 12, 2026

- `npm test`: service workflow tests exercise the real installed SDK and replace only its HTTP connection, including serialization, idempotency headers, capture reconciliation, completed-payment recovery and refunds.
- `npm run build`: production build with Next.js dependency tracing.
- `npm run paypal:check`: authenticated with the configured sandbox application, created an **unapproved** USD 1.00 test checkout and read it back with status `CREATED`. No funds were transferred.
- Buyer approval, capture, refund and webhook delivery against live sandbox remain manual deployment checks. Their mocked tests are not represented as real sandbox transactions.
